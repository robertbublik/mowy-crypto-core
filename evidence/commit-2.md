## Reviewable outcome

Rust generates independent Ed25519, X25519, and archive secrets through the
pinned libsodium randomness layer, immediately places their exact 96-byte
root representation in a zeroizing native type, and permits only the two
public keys to leave initialization. Initialization distinguishes only a
completely empty installation, a completely ready installation, and an honest
unavailable partial state. It does not repair, replace, or silently reset a
partial installation.

The iOS adapter owns one non-synchronizing generic-password Keychain item with
`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`. The Android adapter owns one
non-exportable 256-bit AES Android Keystore key and one exact 126-byte
AES-GCM blob in `noBackupFilesDir`. Android key creation uses the fixed alias,
requires API 28 and an unlocked device, requires randomized encryption and
unlocked-device use, supplies no encryption IV, authenticates the frozen AAD,
and obtains a new provider IV for every atomic rewrap. Both adapters recheck
the lock state before success and return coarse errors only.

This slice deliberately does not expose a key-bearing UniFFI operation. The
current UDL and generated bindings still contain only the parameterless public
profile function. Commit 7 is responsible for connecting these reviewed
native pieces without making raw key bytes visible to Expo or JavaScript.

### Subsequent commit-13 disposition

The Android 12-through-14 row above accurately records the evidence available
at commit 2 and its then-open P2-closeout requirement; that historical result
is not rewritten as a pass. During the later closeout review, no disposable API
31-through-34 device or system image was available, and changing a personal
device's secure-lock configuration remained outside the authorized safety
boundary. The maintainer therefore accepts this cell as **not run — unavailable
for fixture-only P2**, with the implemented stable `unavailable` behavior, no
fallback, and no automatic replacement preserved.

This later disposition supersedes only the timing of the original closeout
requirement. Android 12-through-14 secure-lock removal and
credential/strong/weak biometric or shared-profile behavior remain unproved
and are carried to P8 and independent human review before real recordings,
product integration, or an encryption claim.

## Negative inspection and remaining boundary

- No private key, archive key, plaintext buffer, key import/export, caller
  randomness, file path, or unbounded error appears in the UDL or generated
  bindings.
- No log or evidence string contains the 96-byte fixture or a derived secret.
- Android reads exactly 126 bytes before allocating the blob and rejects links,
  non-regular entries, path escape, and partial alias/file combinations.
- Every Mowy-owned Rust secret container zeroizes on drop; intermediate seeds
  and the root buffer are constructed inside zeroizing owners.
- The available Huawei cannot prove Android 12–14 platform defects, and an
  agent review is not independent assurance. Neither gap authorizes real
  recordings, external testing, hosted audio, an encryption claim, or P3.
